# AgentOps v0.4.3: Policy Engine & Security Gateway Architecture

## Overview
Milestone **v0.4.3** introduces the **Policy Engine** and **Security Gateway** as the authorizing boundary between the AI SRE Agent and the MCP tool execution layer.

```
                  SRE Agent
                     │
               ActionRequest  (Proposed action, target, reason, evidence_refs)
                     │
                     ▼
             Security Gateway  (Authorizing interceptor & audit recorder)
                     │
                     ▼
               Policy Engine   (Evaluates SecurityContext against policies.yaml)
                     │
         ┌───────────┼───────────┐
         │           │           │
         ▼           ▼           ▼
       DENY   REQUIRE_APPROVAL ALLOW
      (Stop)      (Stop)         │
                                 ▼
                             MCP Client
                                 │
                             MCP Server
                                 │
                            Infrastructure
```

---

## 1. Declarative Policy Configuration (`config/policies.yaml`)

Policies are externalized in human-readable YAML:

```yaml
policies:
  # 1. Read-only inspection (ALLOW)
  - id: allow-k8s-read-pods
    agent_ids: [sre-agent-primary]
    action: k8s.read.pods
    risk_level: LOW
    decision: ALLOW
    constraints:
      namespaces: [demo]

  # 2. Remediation actions (REQUIRE_APPROVAL)
  - id: restart-deployment-requires-approval
    agent_ids: [sre-agent-primary]
    action: k8s.remediation.restart_deployment
    risk_level: MEDIUM
    decision: REQUIRE_APPROVAL
    requires_evidence: true
    constraints:
      namespaces: [demo]
      allowed_resources: [demo-app]

  # 3. Explicit Prohibitions (DENY)
  - id: deny-resource-deletion
    action: k8s.remediation.delete_resource
    risk_level: CRITICAL
    decision: DENY
```

---

## 2. Evaluation Flow

1. **Capability Check**: Verifies that the agent possesses a granted `Capability` matching `action_request.action`.
2. **Capability Constraint Check**: Validates `target.namespace`, `target.resource_name`, and `target.parameters` (e.g. `max_replicas`).
3. **Policy Matching**: Identifies all declarative rules matching `action` and `agent_id`.
4. **Deny Overrides**: If any matched rule is `DENY`, evaluation immediately returns `DENY`.
5. **Evidence Check**: If policy specifies `requires_evidence: true`, verifies presence and format of `evidence_refs`.
6. **Decision & Risk**: Assigns `REQUIRE_APPROVAL` or `ALLOW` along with the policy's authoritative `risk_level`.
7. **Gateway Execution**: If decision is `DENY` or `REQUIRE_APPROVAL`, execution stops. If `ALLOW`, forwards to MCP.
8. **Audit Trail**: Writes an immutable `PolicyEvaluationRecord`.
