# v0.7 / v0.7.1 — SRE Operator Console & Unified Incident Workflow

## 1. Overview

Milestone **v0.7 / v0.7.1** transforms AgentOps-SRE from a collection of powerful developer CLI subcommands into a complete, human-centered **SRE Operator Experience**.

It introduces:
1. A modern, dark-mode **Web Operator Console** running at `http://127.0.0.1:8000`.
2. A comprehensive **AgentOps REST API** exposing cluster status, telemetry pulses, LLM discovery, incident investigations, and human approvals.
3. A **Unified Incident Workflow** orchestrator bridging the AI investigation agent, security policies, and controlled remediation.
4. **Live Cluster Observability & Telemetry Pulse** providing real-time Kubernetes pod health, Prometheus error rate, p95 latency, memory usage, and warning counts with deep links.
5. **Provider-Neutral Local AI Runtime Discovery** allowing operators to select between local Ollama models (e.g. `granite4.1:3b`, `qwen3.5:2b`, `ministral-3:8b`), cloud providers, and fast deterministic rule engines with live generation speed (tok/s) and token telemetry.
6. A simplified, one-action **CLI** (`agentops incident <ns>/<workload>`).

## 3. Real Mode vs. Demo Mode

The console establishes strict isolation between production and testing operations:

| Capability | 🔍 Real Incident Investigation | 🧪 Demo Playground |
| :--- | :--- | :--- |
| **Target Scope** | Any discovered namespace & deployment (`default`, `demo`, `monitoring`, etc.) | Strictly restricted to `demo/demo-app` sandbox |
| **Data Source** | Live cluster Kubernetes API, Prometheus queries, Loki logs | Live cluster + Synthetic chaos injector scripts |
| **Chaos Injection** | ❌ Strictly disabled | Allowed scenarios: `crashloop`, `high-error-rate`, `resource-exhaustion`, `bad-deployment`, `reset` |
| **AI Runtime** | Selectable local Ollama models, cloud providers, or rule engines | Selectable AI runtime |
| **Remediation Safety**| Full policy gating & human-in-the-loop approvals | Full policy gating & human-in-the-loop approvals |

## 5. Security & Safety Invariants

1. **Non-Bypassable Gateway**: The UI and REST API cannot invoke `kubectl` mutations directly. All mutations route strictly through `SecurityGateway.execute_remediation()`.
2. **Single-Use Replay Protection**: Approvals transition through `PENDING -> APPROVED -> CONSUMED`. Replay attacks return HTTP 403.
3. **Request Binding**: Any change in action parameters or evidence invalidates the approval token.
4. **Mandatory Post-Verification**: A mutation is only deemed `SUCCESS` if post-remediation verification confirms all pods are healthy and rollout is fully converged.
