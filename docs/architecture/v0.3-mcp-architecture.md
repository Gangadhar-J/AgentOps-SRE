# AgentOps v0.3: MCP Integration Architecture

## Overview
Milestone **v0.3** introduces the **Model Context Protocol (MCP)** as the standardized boundary between the AI SRE Agent and its infrastructure investigation tools.

```
                     SRE Agent
                        │
                    MCP Client  (Discovers tools, invokes tool calls, tracks MCP metrics)
                        │
                  MCP / JSON-RPC (Standardized tool protocol)
                        │
                        ▼
                    MCP Server  (Validates schemas, routes requests, read-only guards)
                        │
          ┌─────────────┼─────────────┐
          │             │             │
          ▼             ▼             ▼
     Kubernetes     Prometheus      Loki
        Tools          Tools        Tools
          │             │             │
          ▼             ▼             ▼
      Kubernetes    Prometheus     Grafana
         API           API          Loki
```

## 1. Registered MCP Tools & Schema Mapping

The MCP Server exposes **8 read-only investigation tools**:

| MCP Tool Name | Purpose | Input Schema | Telemetry Backend |
|---|---|---|---|
| `k8s_get_pod_health` | Inspect pod phases, restart counts, container termination reasons (`OOMKilled`, `Error`), and exit codes | `namespace`, `app`, `pod` | Kubernetes API (`/api/v1/pods`) |
| `k8s_get_deployment_health` | Inspect deployment replica statuses (desired, ready, available) and rollout conditions | `namespace`, `deployment` | Kubernetes API (`/apis/apps/v1/deployments`) |
| `k8s_get_events` | Retrieve recent warning events (`BackOff`, `Unhealthy`, `Failed`, `Killing`) with freshness filtering | `namespace`, `resource_name`, `limit` | Kubernetes API (`/api/v1/events`) |
| `prom_query_error_rate` | Calculate HTTP 5xx error rate percentage over sliding window | `app`, `namespace`, `duration` | Prometheus (`http_requests_total`) |
| `prom_query_latency` | Query p95 request latency percentiles | `app`, `namespace`, `quantile`, `duration` | Prometheus (`http_request_duration_seconds_bucket`) |
| `prom_query_memory` | Query real process RSS memory usage (`process_resident_memory_bytes`) | `app`, `namespace` | Prometheus (`process_resident_memory_bytes`) |
| `loki_search_errors` | Search recent structured application error logs, fatal panics, and memory allocation warnings | `namespace`, `app`, `lookback_seconds`, `limit` | Grafana Loki LogQL |
| `loki_search_by_request_id` | Correlate logs matching a specific request ID or trace ID | `request_id`, `namespace`, `lookback_minutes`, `limit` | Grafana Loki LogQL |

## 2. Runtime Execution Sequence

```
1. SREAgent.investigate(namespace="demo", workload="demo-app")
   │
2. InvestigationOrchestrator invokes SREMCPClient.discover_tools()
   └── MCPServer returns list of 8 registered tools with JSON schemas
   │
3. Orchestrator executes tool calls via SREMCPClient.call_tool():
   ├── call_tool("k8s_get_pod_health", {...}) -> returns Pod health records
   ├── call_tool("k8s_get_events", {...})     -> returns Warning events
   ├── call_tool("prom_query_error_rate",...) -> returns HTTP 5xx error rate
   ├── call_tool("prom_query_memory", ...)    -> returns Real memory metrics
   └── call_tool("loki_search_errors", ...)   -> returns Structured error logs
   │
4. Normalization into typed EvidenceItem records:
   ├── Metric/Query labeled with MCP URI (e.g. `mcp://k8s_get_pod_health`)
   └── Sequential provenance IDs assigned (E001, E002, E003...)
   │
5. LLM Provider synthesizes structured Root Cause Analysis (RCA)
   │
6. AgentObservabilityMetrics attaches MCP request count, tool latency, and failures to the RCA.
```

## 3. Evidence Provenance with MCP

Every fact gathered through MCP preserves its provenance:

```json
{
  "id": "E001",
  "source": "kubernetes",
  "evidence_type": "FACT",
  "resource": "demo/demo-app-5b8b7978db-4q948",
  "metric_or_query": "mcp://k8s_get_pod_health",
  "observation": "Pod 'demo-app-5b8b7978db-4q948' phase: Running, ready: True, restartCount: 0",
  "severity": "INFO"
}
```
