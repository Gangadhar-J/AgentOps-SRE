## 8. Defect & Test Architecture Analysis

During Phase G regression analysis, an important architectural insight was uncovered regarding test suite isolation:

### Finding: Test Telemetry Coupling in Unit Test Suites
- **Symptom:** When the Kind cluster is active and `demo-app` is running in a healthy state (0 restarts, 2/2 replicas, HTTP 200), 9 tests in `tests/unit/test_operator_api.py` and `tests/unit/test_incident_workflow.py` fail with `AssertionError: assert 'FAILED' == 'DRY_RUN_EVALUATED'`.
- **Root Cause Analysis:** The test fixtures in `tests/unit/` instantiate `IncidentWorkflowManager` and `InvestigationOrchestrator`, which use `SREMCPClient()`. `SREMCPClient` defaults to live HTTP endpoints (`localhost:30080`, `localhost:30090`). When the cluster was stopped, the MCP client returned connection errors and fell back to default behavior. When the cluster is running healthy, MCP retrieves real healthy telemetry. The SRE Agent honestly diagnoses `UNKNOWN` (Confidence: 0.4: *"All inspected telemetry indicates normal healthy operation"*). Because no incident exists on a healthy workload, the workflow marks the incident `FAILED` (no fault detected), causing the unit assertion expecting `DRY_RUN_EVALUATED` to fail.
- **Impact:** Low operational impact; does not indicate a production defect. It represents a test double isolation issue: `tests/unit/` should explicitly mock `InvestigationOrchestrator` to decouple unit tests from whatever live workload happens to be running on localhost.
- **Rule Compliance:** In strict accordance with change-control rule 12, no source code or test files were modified during this audit.

## 10. Prioritized Recommendations for Subsequent Milestones

1. **Unit Test Fixture Isolation (Medium Severity):** Update `tests/unit/test_operator_api.py` and `tests/unit/test_incident_workflow.py` fixtures to use an explicit in-memory/mock orchestrator double, preventing unit tests from attempting live MCP queries against `localhost:30080` when a healthy cluster is active.

Consider configuring `LLM_TIMEOUT_SECONDS=400` or enabling token streaming in the worker loop so that intermediate generation progress resets the lease timer.
3. **Automated Kind Cluster Lifecycle in CI (Enhancement):** Integrate `make setup` and `tests/test_infrastructure.py` into a secondary GitHub Actions workflow (`ci-integration.yml`) utilizing a Kind runner action.
